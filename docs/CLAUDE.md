## 1. HARD RULES — violating any of these is disqualification

These are non-negotiable and override every other consideration in this repo.

1. **Gemma 4 must be the primary AI model.** Every AI capability the product advertises must be powered by Gemma 4.
2. **Gemma 4 must be the ONLY LLM / generative foundation model in the codebase.** No GPT, no Gemini, no Claude, no Llama, no Mistral, no Stable Diffusion, no third-party generative TTS/ASR foundation models — not in the app, not in a fallback path, not in a commented-out branch, not in a helper script that ships in the repo.
3. **No separate ASR model for the voice feature.** Gemma 4 (E2B / E4B / 12B) ingests audio natively. Using Whisper or any other speech foundation model would both weaken the Gemma-Integration score and risk the "only LLM" rule. If voice ships, audio goes straight into Gemma 4. If the audio spike fails (see §2), the feature is cut — it is **not** replaced with a third-party ASR.
4. **Permitted non-generative helpers:** classical ML libraries, OCR, computer-vision primitives, speech *processing* (resampling, VAD, encoding), databases, vector stores, APIs, geospatial libraries. These may **support** Gemma 4, never replace it.
5. **Any dataset used must be license-compliant**, and the license must be named in the README.
6. **The demo link must work without login.** Test it in a private browsing window before submitting.
7. **Never fake AI output.** No hardcoded "AI responses", no `setTimeout` fake latency, no pre-baked JSON standing in for a model call. Judges explicitly probe for this. Seeded demo data must be generated by running the *real* pipeline.

## 2. Architecture rules

- **Stack is MERN + Ollama.** MongoDB Atlas · Express · React (Vite) · Node. Gemma 4 is served by **Ollama** (`gemma4:e4b`) behind a single provider adapter.
- **All Gemma access goes through one module.** `server/src/gemma/client.js` is the *only* file permitted to make an inference call. Everything else imports from it. This keeps the rule-compliance surface to a single file and makes the architecture diagram honest.
- **Provider adapter, not provider lock-in.** `GEMMA_PROVIDER=ollama|aistudio` selects transport. Both serve Gemma 4 and only Gemma 4. Ollama is the demo default (proves offline capability); AI Studio is the latency fallback.
- **Prompts live in `server/src/gemma/prompts/` as versioned files**, one file per pipeline stage, each exporting a `version` string. Never inline a prompt in a route handler.
- **Every Gemma call is logged** to the `gemma_calls` collection: stage, prompt version, model, modalities, latency ms, raw response, parse success/failure. This powers the in-app Transparency page, which is our proof-of-realness for the Functionality score.
- **Every Gemma JSON response passes through a validator with a repair pass and a `manual_review` fallback.** A malformed model response must degrade gracefully, never 500.
- **Multimodal ordering:** per the Gemma 4 model card, put image/audio content **before** text in the prompt. Audio clips are capped at **30 seconds**.

### Audio transport — verified findings (2026-07-24)

Hard-won intel. Do not rediscover this the slow way.

- Ollama's **native `/api/chat` silently ignores audio.** An `audios` field produces no error; the model simply reports that no audio was provided.
- Audio on Ollama must use the **OpenAI-compatible endpoint** `/v1/chat/completions`:
  ```json
  {"type": "input_audio", "input_audio": {"data": "<base64>", "format": "wav"}}
  ```
- **Local audio is not demo-viable.** Measured on `gemma4:e2b`, 8 GB Mac: ~5m35s for a 10-second clip, looping and hallucinated transcription, total stall at 47 seconds. llama.cpp currently rejects Gemma 4 audio outright even with `--mmproj`.
- Hosted `gemma-4-e4b-it` on AI Studio serves image input via `types.Part.from_bytes(...)`. **Audio through the hosted API is undocumented** and must be proven empirically before anything depends on it.
- Audio-capable variants only: **E2B, E4B, 12B**. The 26B and 31B models do not accept audio.

## 3. Code conventions

- ES modules throughout (`"type": "module"`). Node 20+.
- Backend: Express, thin routes → `services/` for logic → `models/` for Mongoose schemas. No business logic in route handlers.
- Frontend: React function components + hooks. TanStack Query for server state. No Redux.
- Map: Mapbox GL JS. Keep the token in `.env`; the repo ships `.env.example` only.
- **Never commit secrets.** `.env` **and `secrets.env`** are gitignored in commit #1, before any other file is added. `secrets.env` currently holds a live Kaggle API token; this repo must become public for judging, and a token in git history cannot be un-published by deleting the file later. Rotate the token after the hackathon.
- Bangla is a first-class UI language. All user-facing strings go through `src/i18n/` with `bn` and `en` keys. The citizen app defaults to Bangla; the councilor dashboard defaults to English with a toggle.
- Commit in small, working increments with clear messages. The repo's commit history is visible to judges and is itself evidence the work is real.

## 4. Scope discipline (48-hour build)

- **Do not add a feature that is not in `plan.md`.** If it isn't scoring rubric points, it doesn't get built.
- Anything marked **Tier-A stretch** in `plan.md` has a hard abandon-deadline. When the clock hits it and the feature isn't working, cut it and move on. A working smaller demo beats a broken bigger one — *Functionality is 20 points, and a failed demo scores zero on all four criteria at once.*
- Auth is a demo-grade stub. Do not build real user accounts, password reset, or email verification.
- No test suite beyond a handful of smoke checks on the Gemma pipeline. This is explicitly a prototype sprint; the host's own words are that this "is not about writing polished, production-ready code."
- **Reserve the final 8 hours for the writeup, video, README, and deployment.** These are 20+ points on their own and are what teams reliably run out of time for.

## 5. Working agreement with the user

- Present recommendations with a decision, not a menu of options.
